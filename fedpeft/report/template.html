    The six fixes

    all methods, same rules
    1 · Prior-aware lossEvery client trains with a balanced softmax using its own label prior: CE(f(x) + log πk, y). A class the client has never seen gets log π ≈ −9, so its score is no longer pushed down.
    2 · Class-wise classifier averagingRow c of the shared classifier is averaged only over the clients that have class c, weighted by their count. With plain FedAvg the few cyclists' update was divided by about 20 every round.
    3 · Calibrated decisionsPredictions use f(x) + τ·log πglobal. For V5's nearest-prototype rule τ = 0 validated best.
    4 · Head learning rateFull-model methods (FedAvg, V0) now train their heads at the PEFT rate (discriminative learning rates). With the small fine-tuning rate for everything, rare-class rows barely moved in 40 rounds.
    5 · HMM smoothingActivities last minutes. A hidden Markov model with transitions counted from the training label sequences (36 numbers per client, sent once) smooths each user's predictions. Reported next to the per-window scores.
    6 · V5 for real devicesV5's classifier is personal, so it keeps plain cross-entropy and its own client's prior (a non-cyclist's head is right to rarely predict cycling; fixes 1 and 3 are for shared classifiers). Every device's personal parts get one final update before testing; new users estimate BatchNorm statistics from their own unlabelled windows; few-shot fitting corrects for its balanced label sample.

    LIMU-BERT: 6-s vs 10-s window

    negative result

    LIMU-BERT was pretrained on 6-s windows. Feeding it the whole 10-s window (its 120 position embeddings stretched to 200) helps only the from-scratch model; for the pretrained model in federated training it is worse, so the 6-s window is kept.

    HALO self-supervised pretraining

    MAE + patch contrastive · pool users

    HALO has no public weights, so its encoder was pretrained here on the unlabelled pool users. Both losses should fall steadily.
